# AI A 중간 결과

A는 계획한 지점에서 중단한다. 기능 완성이나 전체 통과를 선언하지 않는다.

- 구현: 메모리 내 카드 전체 스냅샷, 자동 변경 라벨, 편집 기록 창, 현재 기록 강조, 초기화, 중복 상태 제외, 최대 36개·문자 수 예산에 따른 오래된 기록 정리.
- B의 작업: 기록 버튼에서 실제 복원, 현재 커서 변경, 기존 undo/redo와 하나의 기록 흐름으로 통합, 분기 후 미래 기록 삭제 연동.
- 첫 실패: H03. S2 뒤 S1을 클릭해도 색상이 #cf3934로 남는다.
- 첫 전체 실행: H01·H02·H07 PASS, H03·H04·H05·H06·H08·H09·H10 FAIL. BLOCKED 0.
- H07은 현재 기록 재클릭이 상태를 바꾸지 않는다는 뜻이며, 과거 기록 복원이 된다는 뜻은 아니다.
- H10은 PNG가 1080×1350이고 현재 미리보기와 일치하지만, S1 원본 픽셀과 달라 FAIL이다.
- 브라우저: Chromium 153.0.8010.0, Playwright 1.62.1. 각 검사에 새 브라우저 컨텍스트 사용.
- 첫 실행 당시 작업 트리는 미커밋 상태다. results.json의 sourceHashes가 실행한 실제 파일 내용을 식별한다. 최종 커밋의 동일 파일과 해시를 대조할 수 있다.
- 브라우저 다운로드 기본 경로의 설치 오류는 검사 실행 회차가 아니다. npm 배포 Chromium 바이너리를 준비한 뒤 실제 검사를 실행했다.

`a-round-1/results.json` 및 H01~H10 화면을 보관했다. 새 폴더 재현 결과는 추가 증빙으로 남긴다. 오류 회차는 FAIL이 있는 전체 실행 횟수이며, 실패 검사 7개를 오류 7회로 세지 않는다.

## 현재 구현의 제약

기존 편집기의 input 이벤트마다 상태를 기록한다. 이번 고정 검사는 문구 전체 붙여넣기로 한 번에 변경한다. 연속 타이핑을 하나의 기록으로 묶는 UX는 구현하지 않았다. undo/redo는 기존 스택을 계속 쓰므로 기록 창의 현재 강조와 아직 동기화되지 않는다. B는 이 두 기록 체계를 연결하거나 하나로 통합해야 한다. 저장된 draft 복원 이후의 카드가 세션의 초기 상태다. 이미지 데이터는 state의 src에 포함되고 기존 images 캐시를 사용한다.

## 범위 유지

렌더링 엔진·템플릿 저장 스키마·classic 편집기는 수정하지 않았다. 기존 source.zip 다운로드 링크의 대상 파일은 시작 저장소에도 없으므로 이번 개선에서 별도로 만들지 않았다. 저장소 고정 커밋의 전체 소스를 기준으로 사용한다.
